# Sprint 1 — E2: imagens e arquivos estáticos

Data: 03/11/2026. Branch `codex/performance-sprints`, base da E2 `4f1607a`. Implementação e validação locais; nenhuma alteração em produção.

## Entrega

Capas conhecidas da Stays recebem variantes responsivas, dimensões intrínsecas e decodificação assíncrona. Somente a primeira imagem relevante recebe prioridade alta; fotos secundárias do detalhe carregam sob demanda. URLs de outros provedores, assinadas ou com parâmetros existentes permanecem intactas.

O Apache aplica `public, max-age=31536000, immutable` somente a JS/CSS versionados existentes com respostas 200/206/304. Arquivos ausentes em `/assets` retornam 404; HTML e API ficam fora dessa regra.

A construção da imagem reúne os arquivos atuais com os arquivos anteriores durante 30 dias após sua substituição. Um manifesto preserva os prazos originais, remove expirados e rejeita colisões de conteúdo no mesmo nome. O workflow resolve a imagem anterior configurada da aplicação pelo digest; o bootstrap usa o próprio build. Foram acrescentadas verificações de cache aos smoke tests. Esses workflows foram alterados localmente e não executados no GitHub.

## Comparação controlada

Dados completos: [amostras, layouts, cabeçalhos e retenção](sprint-1-e2-2026-11-03.json). Instrumento: [benchmark](sprint-1-e2-benchmark.mjs).

Foram realizadas 12 navegações: antes/depois, mobile/desktop e três repetições por combinação. Os builds foram servidos localmente com gzip, APIs simuladas com atraso fixo de 450 ms e uma mesma foto pública real da Stays. Rede limitada a 500.000 bytes/s e 150 ms de latência; CPU mobile com fator 4. Contextos novos a cada execução. Não são medições da produção nem p75 real.

| Mediana               | Antes    | Depois   | Resultado                                     |
| --------------------- | -------- | -------- | --------------------------------------------- |
| LCP mobile            | 2.352 ms | 2.256 ms | −96 ms; diferença pequena, ganho inconclusivo |
| Bytes da foto mobile  | 135.762  | 71.312   | −47,5%                                        |
| LCP desktop           | 868 ms   | 844 ms   | −24 ms; ganho inconclusivo                    |
| Bytes da foto desktop | 135.762  | 22.039   | −83,8%                                        |

Os percentuais se referem à foto medida, não ao peso total da página. CLS mediano permaneceu em aproximadamente 0,024 no mobile e 0,498 no desktop. A instabilidade desktop exige trabalho na E6. Nas 12 navegações não houve erros JavaScript nem overflow horizontal.

As larguras 320, 390, 768 e 1.280 px também foram verificadas com DPR 2: sem overflow, uma imagem prioritária e variante com resolução suficiente. Downloads isolados confirmaram variantes reais de 640 × 480 e 400 × 300 oferecidas pelo host público.

## Cache e continuidade

Apache nativo 2.4.66 foi usado para testar a configuração real de `.htaccess`. Respostas 200/206/304 de arquivos versionados receberam cache imutável. A verificação final confirmou 404 para arquivo ausente e ausência de cache imutável em HTML/API. Um navegador abriu o build anterior, aguardou a troca local dos arquivos e então importou um módulo antigo ainda não solicitado: resposta 200, conteúdo correto e cache imutável.

A retenção vale para publicações futuras que usem esse fluxo. Um rollback direto para uma imagem antiga pode não conter módulos introduzidos posteriormente; a estratégia de rollback deve considerar o conjunto de assets disponível, sem restaurar banco.

## Validação e pendências

Testes cobrem transformação segura de URLs, prioridade de imagens, retenção/expiração, colisões, nomes inválidos e resolução da imagem anterior por digest. Validação concluída: 486/486 testes frontend passaram; lint/TypeScript, `npm run format:check`, formatação dos arquivos novos, sintaxe shell/JavaScript e `git diff --check` passaram. O build frontend passou durante a etapa, gerando `index-C7oDm64a.js` (462,56 kB; 134,87 kB gzip). Nenhum PHP foi alterado na E2; a validação backend da E1 permanece registrada separadamente.

Não há runtime Docker disponível nesta máquina. A construção completa com `PREVIOUS_ASSETS_IMAGE`, os smoke tests dentro do container e o acesso do CI à imagem anterior ainda precisam passar antes de aprovar publicação. O teste Apache local não substitui esse gate. Não houve push, deploy, mudança de dependências ou migrations.

A E2 reduz transferência de imagens e prepara cache entre versões; não resolve sozinha o excesso de consultas observado na E0. E3/E4 continuam responsáveis pela primeira página independente e pela fila de consultas visíveis.
